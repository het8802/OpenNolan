# UI Polish Audit — codex
Status: PLAN

## Top 10

| Rank | Surface | Flaw | Why it hurts | One-line fix |
| --- | --- | --- | --- | --- |
| 1 | Whole app | The UI has almost no coherent focus system and most dialogs are not real accessible dialogs (`web/src/styles.css:41`, `web/src/App.jsx:493`) | Keyboard users can lose their place, interact behind overlays, or have no visible indication of focus. | Add one global `:focus-visible` token/style and a shared dialog shell with semantics, focus trap, Escape, and focus restoration. |
| 2 | Timeline | Clips, overlays, audio blocks, trim handles, gain lines, and splitters are pointer-only (`web/src/studio/StudioTimeline.jsx:327`, `web/src/studio/Studio.jsx:691`) | The app's core editing surface is unreachable without precise pointer control. | Give timeline objects focus, selection semantics, keyboard move/trim commands, and keyboard-operable separators. |
| 3 | Visual system | `styles.css` has 75 unique hex literals, 41 font-size values, at least 12 radius sizes, and 17 shadow recipes, but only one radius token (`web/src/styles.css:1`) | Small inconsistencies compound into a UI that feels assembled rather than art-directed. | Define semantic color, type, spacing, radius, shadow, and easing scales; migrate surface by surface. |
| 4 | Whole app | Core text and controls fail AA: muted text is 3.58:1 on the app background and white/accent buttons are 3.93:1 (`web/src/styles.css:2`, `web/src/styles.css:5`, `web/src/styles.css:7`, `web/src/styles.css:45`) | Secondary text is pervasive and hard to read; the primary button color is not compliant for normal text. | Darken the muted and accent foregrounds while keeping lighter tints as backgrounds. |
| 5 | Project toolbar | Render is the only filled primary action even though the product rule says “edit live, render rarely” (`web/src/studio/StudioToolbar.jsx:59`, `web/src/studio/StudioToolbar.jsx:64`) | It trains users to render to inspect edits and visually demotes the live source canvas. | Make Source the default truth, rename the terminal action to Export, and style it as a completion action rather than the editor's constant CTA. |
| 6 | Timeline | Delete and keyframe clear execute immediately without a confirmation or visible undo affordance (`web/src/studio/Studio.jsx:373`, `web/src/studio/StudioKeyframes.jsx:68`) | A stray click silently removes meaningful work; undo exists but is not surfaced at the moment of risk. | Show an “Deleted — Undo” toast for reversible deletes and confirm only truly irreversible operations. |
| 7 | Motion | There is no `prefers-reduced-motion` path despite pulsing, rising, smooth scrolling, hover lifts, and perpetual setup animations (`web/src/styles.css:301`, `web/src/chat/ChatPanel.jsx:38`, `desktop/setup.html:35`) | Motion-sensitive users cannot reduce movement, and frequent surfaces feel busier than the editorial aesthetic calls for. | Add reduced-motion overrides and remove motion from high-frequency or keyboard-driven paths. |
| 8 | Dashboard | Project cards use arbitrary rainbow HSL gradients derived from ids (`web/src/App.jsx:229`) | The first screen clashes with the intended warm Anthropic-editorial identity and gives every project a synthetic SaaS-avatar look. | Use a restrained cream/clay/slate cover system with optional project thumbnails from the actual video. |
| 9 | Assets | Browse failures are converted into “empty folder,” and upload has no in-panel busy/progress state (`web/src/components/FolderBrowser.jsx:32`, `web/src/studio/StudioAssets.jsx:34`) | Users cannot tell no content from a network/backend failure, and large media uploads look ignored. | Model loading/empty/error/uploading separately and keep retry/progress inside the panel. |
| 10 | Craft | The studio still ships emoji/text-glyph controls despite the explicit icon rule (`web/src/studio/StudioTimeline.jsx:263`, `web/src/studio/StudioInspector.jsx:489`) | Platform-dependent glyph weight and alignment undermine toolbar consistency and the intended premium feel. | Replace every UI emoji/glyph with the existing 24px-grid stroke icon system. |

## Findings

| Before | After | Why |
| --- | --- | --- |
| **Motion** |  |  |
| Question options use `transition: all 0.12s` (`web/src/styles.css:115`) | Transition only `background-color, border-color, color` with the shared 120–160ms curve. | `all` can accidentally animate layout or future properties and makes motion behavior unpredictable. |
| Legacy option pills also use `transition: all 0.12s` (`web/src/styles.css:194`) | Specify the exact color/border properties. | This repeats the same unsafe motion primitive in a second component family. |
| Pipeline bullets use `transition: all 0.25s` (`web/src/styles.css:282`) | Transition `background-color` and `box-shadow` only, or switch state instantly. | A stage status may change often during work; broad animation adds no spatial explanation. |
| Render progress animates `width` for 400ms (`web/src/styles.css:255`) | Drive a scale-X fill with `transform-origin:left` and a ≤200ms linear transition. | Width animation performs layout and the 400ms lag makes progress feel behind the work. |
| Capability progress animates `width` for 300ms (`web/src/styles.css:1336`) | Use a transform-based fill and the same progress motion token. | This duplicates a non-composited progress implementation with a different duration. |
| First-run progress animates `width` for 350ms (`desktop/setup.html:28`) | Use `scaleX()` or clip-path, with a ≤250ms linear update. | The most performance-sensitive screen animates layout while installation work is already loading the machine. |
| First-run indeterminate progress animates `margin-left` (`desktop/setup.html:38`) | Translate the bar with `transform: translateX(...)`. | Margin animation forces layout every frame; transform expresses the same movement cheaply. |
| No reduced-motion media query exists while pulse, recorder, update-rise, sheen, and slide run (`web/src/styles.css:301`, `web/src/styles.css:920`, `desktop/setup.html:35`) | Add `@media (prefers-reduced-motion: reduce)` to remove translation/scale/pulse and retain restrained opacity/color feedback. | Perpetual motion and pulsing need an accessible alternative. |
| Chat auto-scroll always uses `behavior: 'smooth'` when new content arrives (`web/src/chat/ChatPanel.jsx:35`) | Scroll instantly for keyboard/submission-driven updates; reserve a short smooth move for a user-clicked “jump to latest.” | Streaming messages can trigger this dozens of times and make the conversation feel like it is drifting away. |
| Project tiles lift on every hover without an input-capability gate (`web/src/styles.css:459`) | Put transform hover effects inside `@media (hover:hover) and (pointer:fine)`. | Touch/trackpad-adjacent environments can retain false hover, and motion should be opt-in by capability. |
| Timeline trim affordances appear through ungated hover rules (`web/src/styles.css:1140`, `web/src/styles.css:1150`) | Gate hover-only decoration and keep a non-hover selected/focused affordance. | Touch and keyboard users otherwise never get the same discovery cue. |
| Global button hover uses a brightness filter with no hover media query (`web/src/styles.css:45`) | Use semantic hover colors under a fine-pointer media query. | A blanket filter changes every button's color/contrast differently and creates sticky hover on touch. |
| Buttons and custom pressables have hover but no shared `:active` feedback (`web/src/styles.css:41`, `web/src/styles.css:901`) | Add a 100–140ms `transform` transition and `scale(.97)` active state, suppressing it for drag handles. | Presses currently feel visually identical to hovering; the interface never confirms the down event. |
| Built-in `ease` is used for card and progress motion (`web/src/styles.css:463`, `web/src/styles.css:1338`) | Add `--ease-out: cubic-bezier(.23,1,.32,1)` and `--ease-in-out: cubic-bezier(.77,0,.175,1)`. | The weak browser curves make the few animations present feel generic instead of intentional. |
| Asset previews autoplay after arrow-key navigation in the dialog (`web/src/components/AssetModal.jsx:31`, `web/src/components/AssetModal.jsx:59`) | Do not autoplay media when navigation came from the keyboard; focus Play and let the user start it. | Keyboard-initiated actions should not trigger motion/audio automatically. |
| **Visual system** |  |  |
| `:root` defines colors and one `--radius`, but no spacing, type, shadow, or easing scale (`web/src/styles.css:1`) | Add semantic scales such as `--space-1…`, `--text-xs…`, `--radius-sm/md/lg`, `--shadow-popover/modal`, and motion tokens. | The stylesheet has tokens in name only; most design decisions remain ad hoc. |
| The stylesheet contains 75 unique hex literals; even a low-saturation heuristic finds 7 opaque greys before counting the many warm-neutral variants (`web/src/styles.css:1`, `web/src/styles.css:1341`) | Reduce colors to semantic roles and a small warm-neutral ramp. | Repeated near-neutrals such as `#f0ece4`, `#f6f2ec`, `#efe9df`, and `#fbf7f0` are visually indistinguishable but impossible to govern. |
| There are 41 distinct `font-size` values, ranging from `0.58rem` to `3rem` (`web/src/styles.css:59`, `web/src/styles.css:718`) | Collapse UI typography to 5–7 named sizes with explicit line-height and weight roles. | Tiny one-off steps produce hierarchy noise; several labels fall below a practical 11px reading size. |
| Radius declarations span at least 12 scalar sizes plus multiple one-off corner recipes (`web/src/styles.css:56`, `web/src/styles.css:362`, `web/src/styles.css:1330`) | Use 3–4 radii plus `--radius-pill` and a modal radius. | Almost every component invents its own curvature, weakening family resemblance. |
| There are 17 shadow recipes/variants, including three nearly identical `0 2px 10px` tints (`web/src/styles.css:106`, `web/src/styles.css:219`, `web/src/styles.css:347`) | Define elevation levels and use border/tint for semantic state instead of colored shadow variants. | Shadows should communicate elevation; here they also encode component identity inconsistently. |
| Muted `#8a8178` is 3.58:1 on `#faf7f2` and 3.76:1 on `#fffdf9` (`web/src/styles.css:2`, `web/src/styles.css:3`, `web/src/styles.css:5`) | Darken the muted foreground to at least 4.5:1 for normal-size labels. | Muted text is used for timecodes, hints, metadata, and navigation—far too much content to treat as decorative. |
| White on the accent, and accent on white, are both 3.93:1 (`web/src/styles.css:7`, `web/src/styles.css:45`) | Split accent into a darker interactive foreground/fill and a lighter decorative clay. | Primary actions and accent links fail AA at normal text sizes. |
| Amber on amber-soft is only 2.42:1 (`web/src/styles.css:11`, `web/src/styles.css:12`, `web/src/styles.css:959`) | Use a dark ochre foreground on the pale amber surface. | Warnings are among the most important messages but have the weakest contrast. |
| Green on green-soft is 3.51:1 (`web/src/styles.css:13`, `web/src/styles.css:14`, `web/src/styles.css:957`) | Use a darker success foreground while retaining the soft green fill. | “Saved” and success states do not meet AA for normal text. |
| Inputs and panels repeatedly hard-code `#fff` rather than semantic surface tokens (`web/src/styles.css:41`, `web/src/styles.css:314`, `web/src/styles.css:1024`) | Replace direct white with `--surface-raised` / `--field-bg`. | This fragments the warm ivory palette and blocks coherent dark/high-contrast adaptation. |
| Focus is styled only for asset tiles and scrub bars; native controls otherwise rely on inconsistent UA focus (`web/src/styles.css:349`, `web/src/styles.css:1037`) | Add a global `:focus-visible` ring that works on buttons, links, selects, and inputs. | Keyboard traversal visually disappears across most of the app. |
| Several text fields explicitly remove outlines on `:focus` (`web/src/styles.css:125`, `web/src/styles.css:229`, `web/src/styles.css:1287`) | Preserve outline for keyboard focus and move visual-only border changes to `:focus-visible`. | Removing the outline without an equally visible replacement is an accessibility regression. |
| Disabled states are mostly opacity-only (`web/src/styles.css:46`, `web/src/styles.css:908`) | Pair semantic disabled colors with opacity, and keep labels at readable contrast. | At 0.4–0.42 opacity, labels become illegible and state is conveyed by fading alone. |
| The web app has no declared light/dark color scheme while the setup window explicitly forces light (`desktop/setup.html:12`, `web/src/styles.css:1`) | Explicitly declare the app's intentional light editorial scheme, then add forced-colors/high-contrast support. | The aesthetic is intentionally light, but system form controls and scrollbars can still render incoherently. |
| **Hierarchy & layout** |  |  |
| Render is the only filled project-toolbar CTA (`web/src/studio/StudioToolbar.jsx:59`) | Treat live Source as the editor's working state and position Export/Render as a terminal action. | The hierarchy contradicts “edit live, render rarely” and makes previewing feel render-dependent. |
| Source/Render is visually a segmented control but has no group label or selected-state semantics (`web/src/studio/StudioToolbar.jsx:59`) | Use a named tablist or pressed-button group and make Source's live status explicit. | The mode switch looks like two ordinary buttons and does not announce which preview is authoritative. |
| The project toolbar and every group can wrap (`web/src/styles.css:889`, `web/src/styles.css:895`) | Keep a single-line toolbar with priority-based overflow or a “More” menu. | Wrapping changes spatial memory and can separate Save/Export from the project context at smaller widths. |
| The Assets panel puts “Canvas background” before its own “Assets” heading (`web/src/studio/StudioAssets.jsx:40`) | Put the panel title first and make Canvas background a collapsible, clearly separate section. | The first visible control belongs to project settings, so the panel's purpose reads late. |
| Inspector sections all share the same border/title treatment and fields commit immediately (`web/src/studio/StudioInspector.jsx:415`) | Emphasize identity/timing first, collapse advanced sections, and show a subtle saved/live indicator. | Dense forms lack scan hierarchy and do not reassure users that edits are already applied. |
| Preview's no-render empty state says “hit Render” (`web/src/studio/StudioPreview.jsx:517`) | Explain that Source is the live editable preview and Render is only needed for the final composed bytes. | The copy directly undermines the preview-equals-export/live-edit north star. |
| Asset browse errors collapse to an empty array (`web/src/components/FolderBrowser.jsx:32`) | Preserve `loading`, `error`, and `empty` as separate states with retry. | A broken backend currently masquerades as a valid empty folder. |
| Upload only calls the API and refreshes later, with no local busy/progress tile (`web/src/studio/StudioAssets.jsx:34`) | Insert an optimistic uploading tile with filename, progress/spinner, cancel/error, and retry. | Video files can be large; silence after drop reads as failure. |
| Render and capability progress display fabricated percentages (`web/src/chat/ChatPanel.jsx:150`, `web/src/CapabilityInstall.jsx:33`) | Use labeled indeterminate phases until real byte/stage progress exists. | A steadily creeping number implies precision the system does not have and erodes trust when it stalls at 90–92%. |
| Dashboard project identity is an initial over random HSL gradients (`web/src/App.jsx:228`) | Prefer a real frame/poster; fall back to a restrained warm editorial template. | The most prominent visual surface feels unrelated to the videos and to the stated Anthropic-ish direction. |
| The dashboard header has four similarly quiet account/settings actions in one row (`web/src/App.jsx:185`) | Group account/capabilities/BYOK/feedback under a compact settings menu; reserve the header for New project and identity. | Re-auth, Capabilities, Feedback, and BYOK compete with the main dashboard task. |

## Deliberately not changing

- The cream/ivory base with terracotta/clay accent is the right direction (`web/src/styles.css:2`, `web/src/styles.css:7`). I would refine contrast and reduce literals, not replace the palette with dark/neon styling. I would reconsider only if the product brief changes.
- The preview stage itself should stay dark (`web/src/styles.css:988`): neutral media surround improves edge perception and is not evidence the app needs a dark theme. I would change it only after testing color judgment against a lighter surround.
- `transform-origin: center` on canvas overlay scale (`web/src/studio/StudioPreview.jsx:433`) is content-animation geometry, not a trigger-anchored popover. It should remain centered unless renderer geometry changes.
- Authored video keyframe presets—including `ease-in` for a fade-out and the 350–500ms overlay presets—are export content, not application chrome (`web/src/studio/model.js:173`). The UI-motion rubric should not silently rewrite a creator's video language.
- Tabular numerals are already correctly applied to studio timecodes, ruler ticks, durations, and scrub values (`web/src/styles.css:1013`, `web/src/styles.css:1083`, `web/src/styles.css:1139`). Extend this pattern; do not replace it.
- The main drag surfaces already use `user-select:none`, `touch-action:none`, and grab/resize cursors (`web/src/styles.css:1003`, `web/src/styles.css:1134`, `web/src/styles.css:1144`). The gap is on splitters and hit-target/accessibility layers, not the core pointer model.
- Asset names, project names, and most file paths already truncate rather than blow out their containers (`web/src/styles.css:359`, `web/src/styles.css:605`, `web/src/styles.css:1210`). I would preserve those behaviors and fix only the remaining title/toolbars after real overflow tests.
- The old editor's JavaScript is dead from the current entry path, so I would not refactor its components in a polish pass (`web/src/App.jsx:5`, `web/src/editor/Editor.jsx:15`). Remove its shipping CSS and delete the code only in a separately reviewed cleanup if repository history/tests confirm no alternate entrypoint.
