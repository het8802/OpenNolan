# Greg Isenberg Product Explainer — Creative Skill

## When to Use

Use this skill for vertical AI/startup/product explainers that should feel like a Greg Isenberg / premium editorial product reel: warm off-white canvas, large serif ideas, crisp product UI mockups, workflow diagrams, founder/startup metaphors, proof receipts, and phrase-synced motion.

Use it when Het asks for the “Greg theme,” “Greg Isenberg style,” “Hyperagent-style,” premium AI-product informational Reels, or OpenMontage videos that must stay aligned with the warm editorial AI/startup vibe.

Do **not** use pixelated RPG characters, purple crystals, obsidian/fantasy UI, violet glow, or purple keyword accents in this skill. Those belong to a separate reference world and should not leak into Het’s Greg-theme output.

## Core Principle

Make the idea feel like a designed product system: **problem/proof → workflow map → prompt/action → evaluation/output → tangible artifact → public proof/payoff**. Motion should reveal how the system works, not decorate frames randomly.

## Visual Language

- Canvas: 1080×1920 vertical, warm ivory/off-white paper.
- Palette: charcoal text, forest green system elements, mint/sage highlights, coral only for fail/reject/negative, gold for value/attention, warm-gray UI depth.
- Typography: editorial serif for narrative claims and phrase captions; modern sans for UI labels, pills, product names, and metadata.
- Shapes: rounded UI cards, sticker badges, dashed containers, orthogonal connectors, circular nodes, clean vector props.
- Texture: subtle paper grain, soft shadows, lightweight sticker/receipt feel.
- Avoid: neon AI, dark cyberpunk, purple/violet/lavender glow, Obsidian-like fantasy darkness, tiny dense screenshots, generic robots.

## Reference Learnings to Preserve From Reel `DY5SPASumP8`

Preserve the **editorial grammar**, not the RPG/Obsidian skin.

| Reference behavior | Greg-theme translation |
|---|---|
| Threat/world-state opens the video before the tutorial | Open with a warm-paper problem board, proof receipt, or large serif claim. Let threat labels enter as stickers/pills. |
| Proof/news windows stack over the scene | Use browser/report/source receipt cards with soft shadows, slight offsets, and one highlighted phrase per card. |
| “3 levels” structure makes the workflow clear | Use `3 steps`, `3 layers`, `3 standards`, or `3 moves` as chapter logic. |
| Tool A connects to Tool B through an MCP/computer node | Use a clean product workflow diagram: app/tool → connector/agent → output artifact. |
| Radial trend map shows the niche | Use a dark forest/charcoal circular board with mint/sage topic pills and a subtle camera push. |
| Prompt bar becomes response becomes checklist | Keep the prompt/result/artifact transformation as the main teaching mechanic. |
| Moral reset before final action | Use a high-negative-space white beat with one strong sentence. |
| Final proof/dashboard closes the loop | End on profile, post grid, dashboard, checklist, or public proof board — not a generic CTA. |


## Asset Sourcing Protocol — Required for Production

Before composing a Greg-theme reel, build an asset evidence kit. The reel should not be only animated text and generic cards.

1. **Extract source screenshots from links**
   - If the script references articles, product pages, reports, repos, launch pages, tweets/posts, or docs, capture cropped screenshots as proof receipts.
   - Use them as layered cards, not full-screen dense screenshots. Overlay the actual readable claim in OpenMontage text.
   - Store screenshot assets under `projects/<project>/assets/images/source-receipts/` with source URL and timestamp in the asset manifest.

2. **Source relevant footage when the beat is real-world**
   - For concrete context beats, source short B-roll clips: founder working, office/productivity, coding, data center, phone/social feed, meeting, city/startup context, etc.
   - Prefer commercial-safe stock/project-corpus/public-domain sources first. Use YouTube only when licensing/permission is clear; otherwise use it for research/reference and recreate the beat with stock/generated assets.
   - Trim clips into 1–3s inserts or texture strips; grade/crop them into the warm Greg palette.

3. **Generate AI images for abstract/product beats**
   - Create 1 hero image for the visual system and 3–8 scene-specific supporting images when the video would otherwise feel text-only.
   - Good generated assets for this style: warm editorial product hero scenes, simplified UI cards, founder metaphor props, workflow boards, agent/evaluation icons, abstract concept backdrops.
   - Never ask the image model to render final text; add readable text in OpenMontage.

4. **Use an asset mix per 45–60s reel**
   - Minimum target: 2–4 source screenshots/receipts, 2–4 b-roll clips or extracted footage moments, 3–6 generated/stylized images or UI mockups, plus reusable overlays/icons.
   - Every scene should have a concrete visual asset unless it is intentionally a moral-reset text beat.

5. **Manifest discipline**
   - Track each asset with `scene_id`, `type`, `source_tool`, `source_url`, `license/provenance`, and intended on-screen role: `proof`, `broll`, `generated_hero`, `ui_mockup`, `texture`, or `overlay`.

## Structure Pattern

1. **Problem/proof hook**
   - First frame should contain a surprising founder/product claim, a proof receipt, or a clean metaphor prop.
   - Bring in 2–4 threat or context labels as stickers/pills: `AI agents`, `distribution`, `CAC`, `workflow debt`, `competition`.
   - Use one immediate motion trigger: cursor click, card snap, agent badge pulse, or source receipt landing.

2. **Receipt stack / premise proof**
   - Stack source cards, charts, screenshots, or browser receipts.
   - Cards slide from different edges by 80–180px, rotate -2°→0°, and settle with soft shadow growth.
   - Highlight only one phrase per receipt. Generated microtext is decorative; overlay real text in OpenMontage.

3. **Chapter line**
   - Large serif text builds in phrase chunks: `There are` → `3 layers` → `to this`.
   - Emphasis words use mint, forest, gold, italic, underline, or tiny scale punch.
   - No bottom subtitle bar. Captions should feel hand-composed around the focal visual.

4. **Workflow diagram**
   - Show input → agent/system → output.
   - Draw connectors over 0.3–0.6s; pop each node after the line reaches it.
   - Put nodes inside a dashed rounded system boundary when the point is automation or evaluation.

5. **Prompt/result loop**
   - Prompt bar is a hero UI object: black/forest rounded pill, active mint rim, typewriter text, cursor blink.
   - Keep prompt text short enough to read at phone size.
   - The AI response should immediately become a tangible artifact.

6. **Artifact transformation**
   - Transform result card into checklist rows, plan cards, calendar blocks, output grid, or post drafts.
   - Stagger rows/cards in 0.08–0.14s increments.
   - Use check circles, progress fills, or card sorting to show utility.

7. **Moral reset**
   - Use mostly empty warm-white canvas with one large line.
   - Example pattern: `Learning quietly won’t compound.` → then proof/public output appears.
   - Hold 0.8–1.4s; let it breathe before the final payoff.

8. **Proof-of-work payoff**
   - End on a proof board/profile/content grid/dashboard that shows the workflow produced something public or useful.
   - Final camera push-in: 3–5%.
   - CTA should be tied to an artifact/comment keyword if used, not “follow for more.”

## Motion Vocabulary

| Motion | Use For | Parameters |
|---|---|---|
| `receipt-stack-in` | Proof/source cards | slide 80–180px, opacity 0→1, rotate -2°→0°, shadow grows, 0.28–0.45s ease-out |
| `phrase-collage-build` | Editorial captions | 2–5 word groups; y 14–22px→0; blur 2–3px→0; stagger 0.06–0.12s |
| `keyword-hit` | Important nouns | mint/forest/gold color, italic/underline, scale 1→1.03–1.06→1, 0.18–0.25s |
| `connector-draw` | Workflow paths | dashoffset draw-on 0.3–0.6s; node pops after endpoint |
| `system-boundary-draw` | Automation/evaluation zone | dashed rounded rectangle strokes in, label pill lands top-left |
| `radial-pill-populate` | Trend/niche map | central topic lands, pills populate in 0.08–0.14s stagger, optional slow orbit/float |
| `prompt-bar-type` | User action/prompt | pill slides in, cursor types, mint rim intensifies during typing |
| `response-to-artifact` | AI output utility | response card shrinks/repositions; checklist/grid rows wipe in one-by-one |
| `proof-board-land` | Final payoff | board scales 0.94→1, y 40→0, shadow settles, camera pushes 3–5% |

## Easing and Timing

- Default entrances: cubic / `power3.out`, 0.28–0.45s.
- Use hard snaps only for proof hits, chapter resets, prompt submit, or status changes.
- Avoid meme yoyo bounces, random glitch, giant overshoot, and purple/violet flash frames.
- Every 0.5–1.5s, change one meaningful element: word group, card, connector, prompt text, result row, or camera crop.
- Transitions should be short: 4–8 frames for blur/cut resets, 8–14 frames for object-driven slides.

## Camera and Composition

- Treat the scene as an oversized designed canvas and move a virtual camera across it.
- Three camera states:
  1. **System wide:** claim + proof/diagram context visible.
  2. **UI close:** prompt/result/product card fills 60–80% width; edge cropping allowed.
  3. **Artifact hero:** checklist/profile/grid/dashboard centered with a concise caption.
- Push-ins: 3–7% over a scene.
- Snap zooms: only on receipt hit, prompt submit, or final proof board.
- Layer depth: paper background → connectors/grid → cards/props → captions → foreground prompt/result UI.
- Keep all primary text inside Reels safe zones; do not rely on tiny screenshot text.

## Audio and SFX

- Narration: fast, founder-native, crisp, slightly urgent; short clauses that map to motion events.
- Music: low-volume warm electronic/productivity pulse.
- SFX: soft pops, whooshes, cursor clicks, typing ticks, checklist row ticks, proof-board landing hit.
- Do not hit every caption word. Reserve SFX for transitions and artifact transformations.

## Runtime Guidance

Prefer **HyperFrames** for HTML/CSS/GSAP kinetic typography, prompt bars, floating cards, and editorial UI staging.

Prefer **Remotion** when reusing React scene components, deterministic captions, charts, screen mockups, or an existing OpenMontage Remotion project.

If both are available, follow `AGENT_GUIDE.md`: present both options before locking the render runtime.

## Quality Rubric

| Check | 1 | 3 | 5 |
|---|---|---|---|
| Greg vibe | Generic SaaS/neon | Warm but inconsistent | Warm editorial AI/product system with strict palette and typography |
| Proof clarity | Random screenshots | Relevant but small | Each proof card is legible enough and tied to narration |
| Asset richness | Mostly text/cards | Some receipts or generated visuals | Balanced mix of screenshot receipts, b-roll/footage inserts, generated images/UI mockups, and designed overlays |
| Caption motion | Bottom subtitles | Phrase chunks with some emphasis | Designed phrase collage synced to spoken stress |
| Workflow legibility | Pretty but vague | Steps mostly clear | Viewer understands input → system → artifact → payoff |
| Motion taste | Bouncy/janky | Consistent but plain | Premium soft-settle motion with meaningful changes every 0.5–1.5s |
| Brand discipline | Purple/neon/pixel leaks | Minor off-theme moments | No purple/violet/obsidian/pixel RPG motifs; coherent Greg palette throughout |
| Mobile safety | Text under UI | Mostly safe | Keywords, prompts, and payoff readable under Reels UI |

## Common Pitfalls

- Importing pixel RPG, purple crystal, or Obsidian/fantasy aesthetics from the reference reel.
- Using one-line bottom subtitles instead of designed phrase captions.
- Making screenshots carry the actual message; overlay readable OpenMontage text.
- Skipping the asset evidence kit: source screenshots, b-roll/footage, and generated images are required for visual richness.
- Using unlicensed third-party YouTube footage directly; if licensing is unclear, recreate the beat with stock/generated assets.
- Overusing bounces/glitches; this style is premium, restrained, and editorial.
- Filling the warm canvas with too many cards; negative space is part of the look.
- Ending on advice. End on an artifact, public proof, or identity/status outcome.

## QA Checklist

- Render a 1fps contact sheet and verify the sequence shows: hook/proof, workflow map, prompt, result artifact, moral reset, proof payoff.
- Verify the asset manifest includes screenshot receipts, b-roll/footage inserts where relevant, generated images/UI mockups, and provenance/license notes.
- Watch at phone size; prompt text and payoff captions must remain readable.
- Verify no purple/violet/lavender/obsidian/crystal/pixel RPG motifs appear unless explicitly requested.
- Check contrast for mint/sage/gold text on warm backgrounds.
- Confirm all source cards are original/stylized or legally usable; no copied creator assets.
